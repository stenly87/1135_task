# Разработка API
Разработайте локальный сервер (API) для взаимодействия всех компонентов системы с базой данных на основании предоставленных вам технологических стеков и общей архитектуры системы. 
Ниже приведены данные, необходимые для хранения. В ходе работы вам потребуется доработать базу данных, добавить необходимые сущности и поля.
API — единая точка доступа для всех трёх клиентов (desktop, web, mobile) к общей базе данных. Гарантирует консистентность данных, единые правила авторизации и безопасность.

# Обязательные функции API:
# Аутентификация (общая для всех клиентов):
-	POST /auth/login — вход по email+пароль, возврат JWT
-	POST /auth/refresh — обновление токена
-	POST /auth/logout — выход
# Профиль (доступно всем клиентам):
-	GET /users/me — текущий профиль
-	PUT /users/me — обновление профиля
-	GET /users/{id} — профиль другого пользователя
-	GET /users/{id}?mode=employer — обезличенный профиль для работодателя (скрыты контакты)
# Данные профиля (доступно web/mobile для редактирования):
-	POST/PUT/DELETE /education, /experience, /skills
# Подтверждения (социальная верификация):
-	POST /confirmations/request — запрос подтверждения
-	POST /confirmations/{id}/accept — подтвердить
-	POST /confirmations/{id}/reject — отклонить
-	GET /confirmations — список запросов и подтверждений
# Рейтинг (агрегация):
-	GET /users/{id}/rating — актуальный рейтинг
-	GET /users/me/rating/history — история изменений

# Требования к API:
JWT авторизация для всех операций (кроме login);
-	валидация всех входных данных;
-	унифицированный формат ответа: {success: boolean, data: {}, message: string, error_code: string};
-	обработка ошибок 400/401/403/404/500;
-	логирование всех операций.

# Реализация ограничений на уровне БД
Все проверки целостности и бизнес-логики реализуйте SQL-ограничениями и триггерами:
-	уникальность контактов — email/телефон уникальны для пользователя;
-	непересечение опыта — периоды работы одного пользователя не пересекаются;
-	допустимый уровень навыков — 0–10;
-	логическая последовательность дат — дата окончания позже начала, регистрация не в будущем;
-	автоматический пересчёт рейтинга — при подтверждении/отклонении обновляется индекс компетенций;
-	логирование изменений ролей — все смены ролей фиксируются в отдельной таблице;
-	запрет самоподтверждения — пользователь не может подтвердить самого себя.

Триггеры должны работать атомарно, обеспечивая целостность без влияния на производительность API.
